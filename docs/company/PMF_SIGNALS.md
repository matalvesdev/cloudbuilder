# PMF Signals

> Status: Active | Owner: Product | Last Updated: 2026-08-14

## Definition

Product-Market Fit exists when the product delivers sufficient value that users would be "very disappointed" if it disappeared.

## Sean Ellis Test

> "How would you feel if you could no longer use CloudBuilder?"

- **Very disappointed** → PMF candidate
- **Somewhat disappointed** → Close, iterate
- **Not disappointed** → No PMF yet

**Target:** > 40% "very disappointed" = PMF signal

## PMF Signals to Track

### Strong Signals (High Confidence)

| Signal | How to Measure | Target | Status |
|--------|---------------|--------|--------|
| **Organic referrals** | Users inviting team without prompting | > 20% invite rate | UNVALIDATED |
| **Strong retention** | Week 4 retention of provisioned users | > 30% | UNVALIDATED |
| **Pull from users** | Unsolicited feature requests, bug reports | Regular cadence | UNVALIDATED |
| **Willingness to pay** | Users upgrading or asking about pricing | > 5% conversion | UNVALIDATED |
| **Repeated use** | Multiple provisions per user per week | > 2/week | UNVALIDATED |
| **Clear use case** | Users can articulate what they use it for | Qualitative feedback | UNVALIDATED |

### Medium Signals (Moderate Confidence)

| Signal | How to Measure | Target | Status |
|--------|---------------|--------|--------|
| **Time spent in app** | Daily active users / weekly active users | > 30% DAU/WAU | UNVALIDATED |
| **Feature adoption** | Users using 3+ features regularly | > 40% | UNVALIDATED |
| **Support requests** | Quality of questions (not just "how to") | Increasing sophistication | UNVALIDATED |
| **Community activity** | Discord messages, GitHub issues | Growing engagement | UNVALIDATED |
| **Content engagement** | Blog reads, documentation visits | Increasing traffic | UNVALIDATED |

### Weak Signals (Low Confidence)

| Signal | How to Measure | Target | Status |
|--------|---------------|--------|--------|
| **GitHub stars** | Repository stars | Growing | UNVALIDATED |
| **Social mentions** | Twitter/LinkedIn mentions | Increasing | UNVALIDATED |
| **Newsletter subscribers** | Email list size | Growing | UNVALIDATED |
| **Conference interest** | Speaking invitations, attendee questions | Growing | UNVALIDATED |

## Anti-Signals (No PMF)

| Anti-Signal | What it means | Action |
|------------|--------------|--------|
| **High bounce rate** | Users don't understand value proposition | Fix onboarding/messaging |
| **Low activation rate** | Users don't reach first value | Fix core loop |
| **High churn after first use** | Value isn't recurring | Add retention drivers |
| **Feature requests without usage** | Users want what we don't have, not what we do | Focus on core workflow |
| **"It's cool but..."** | Interesting but not essential | Find essential use case |
| **Only founder-driven growth** | No organic acquisition | Build distribution loops |

## PMF Experiments

| Experiment | Hypothesis | Metric | Duration |
|-----------|-----------|--------|----------|
| **Remove canvas** | Canvas is the core value | Retention without canvas | 2 weeks |
| **Remove provision** | Provision is the core value | Retention without provision | 2 weeks |
| **Add pricing** | Users will pay for value | Conversion rate | 4 weeks |
| **Add team features** | Collaboration drives retention | Team adoption rate | 4 weeks |

## PMF Checklist

- [ ] > 40% "very disappointed" in Sean Ellis test
- [ ] > 30% week 4 retention
- [ ] > 20% organic referral rate
- [ ] > 5% free-to-paid conversion
- [ ] Users can articulate value proposition
- [ ] Users return without founder prompting
- [ ] Support requests are about advanced features, not basics
- [ ] Users invite team members organically
- [ ] Users would be upset if product disappeared

## Pre-PMF Principles

1. **Learning > Scaling** — Understand users before growing
2. **Manual > Automation when useful** — Founder-assisted onboarding is fine
3. **Focus > Breadth** — One workflow, done well
4. **Evidence > Opinion** — Measure everything, assume nothing
5. **Talk to users** — 10 conversations > 1000 data points

## Post-PMF Transition

When PMF signals are strong:
1. Document what works
2. Build repeatable acquisition
3. Add billing and pricing
4. Hire first employees
5. Scale distribution
6. Expand product surface
