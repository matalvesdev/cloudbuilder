# Go-To-Market Strategy

> Status: Active | Owner: Founders | Last Updated: 2026-08-14

## GTM Motion

**Content-Led Growth + Founder-Led Sales.**

The primary motion is: Developer discovers content → Signs up for free trial → Experiences value → Converts to paid → Invites team → Upgrades for more resources/features.

## Distribution Strategy (Closed-Source)

Since CloudBuilder is **closed-source**, we rely on:

1. **Content marketing** — Technical blog, tutorials, architecture guides
2. **SEO** — Target infrastructure/platform engineering keywords
3. **Community** — Discord, LinkedIn, X for developer engagement
4. **Founder-led content** — Building in public, technical deep dives
5. **Direct sales** — Inbound from content + outbound for enterprise
6. **Demo-first** — Free trial with limited resources

### What We Don't Do

- ❌ Open-source GitHub repository
- ❌ Community code contributions
- ❌ Fork-based distribution
- ❌ Open-core model

## Funnel

### Awareness
- **Channel:** Technical blog, LinkedIn, X, Discord, Hacker News, Reddit
- **Message:** "Design cloud infrastructure visually. Get production-ready Terraform. Deploy in minutes."
- **Content:** Architecture deep dives, tutorials, "building in public" updates
- **Metric:** Website visitors, social mentions, Discord members

### Acquisition
- **Channel:** Blog posts, SEO, social media, founder content
- **Message:** "Free 14-day trial. No credit card required."
- **CTA:** Start free trial
- **Metric:** Trial signups (target: > 5% of visitors)

### Signup
- **Channel:** Website (cloudbuilder.dev)
- **Message:** "Create your first infrastructure design in 5 minutes"
- **CTA:** Sign up (email + password only)
- **Metric:** Signup conversion rate (target: > 30% of visitors)

### Activation
- **Channel:** Onboarding wizard
- **Message:** "Design → Generate → Provision in 3 steps"
- **Event:** First canvas created with 2+ connected resources
- **Metric:** Activation rate (target: > 50% of signups)

### First Value
- **Channel:** Canvas + Generate + Provision workflow
- **Message:** "Your design is now real infrastructure"
- **Event:** First successful provision
- **Metric:** Time to first provision (target: < 30 min)

### Conversion (Trial → Paid)
- **Channel:** In-app upgrade prompts + email sequence
- **Message:** "Upgrade to keep your infrastructure managed"
- **Event:** Subscription started
- **Metric:** Trial-to-paid conversion (target: > 10%)

### Habit
- **Channel:** Auto-save, drift detection, cost tracking
- **Message:** "Your infrastructure is being monitored"
- **Event:** 3+ provisions in 7 days
- **Metric:** Week 2 retention (target: > 40%)

### Expansion
- **Channel:** Team invitations, tier upgrade prompts
- **Message:** "Invite your team. Upgrade for more resources."
- **Event:** Team member invited OR tier upgrade
- **Metric:** Team adoption rate (target: > 20%)

### Advocacy
- **Channel:** Blog, Discord, social media
- **Message:** "Built our infrastructure with CloudBuilder"
- **Event:** Public testimonial, blog post, conference talk
- **Metric:** NPS, referral rate

## Beachhead Market

**Platform engineers at Brazilian B2B SaaS startups (Series A–C).**

### Why This Market

1. **High pain** — Small teams, limited time, growing infrastructure
2. **Accessible** — Founder's network, same language, same timezone
3. **Representative** — Problems are universal, solution scales globally
4. **Underserved** — No visual infrastructure tool targeting this segment

### ICP Definition

| Attribute | Description |
|-----------|------------|
| **Company size** | 10–200 engineers |
| **Stage** | Series A–C or equivalent revenue |
| **Industry** | B2B SaaS |
| **Cloud** | AWS, GCP, or multi-cloud |
| **Infrastructure** | 50–500 cloud resources |
| **Team** | 1–5 platform/DevOps engineers |
| **Geography** | Brazil (primary), Latin America (secondary), Global (tertiary) |

## Content Strategy

### Pillars
1. **Platform Engineering** — Best practices, patterns, tooling
2. **Infrastructure as Code** — Terraform, OpenTofu, multi-cloud
3. **Cloud Architecture** — Design patterns, cost optimization, security
4. **Building in Public** — Engineering decisions, product development, lessons learned

### Content Types
- **Tutorial:** Step-by-step guides (e.g., "Deploy GCP Infrastructure in 10 Minutes")
- **Deep dive:** Architecture decisions, technical trade-offs
- **Comparison:** CloudBuilder vs. manual Terraform, vs. other tools
- **Benchmark:** Provisioning speed, cost estimation accuracy
- **Case study:** Real user workflows (when available)

## Founder-Led Marketing

Founders should post 2–3 times per week on LinkedIn and X about:
- What we're building and why
- Technical challenges and solutions
- User feedback and learnings
- Industry observations
- Failures and pivots

Build credibility through building in public, not through marketing claims.

## Launch Strategy

### Pre-launch (Now)
- Build in public on LinkedIn/X
- Publish technical content on blog
- Grow Discord community
- Recruit 10 design partners

### Alpha (Month 2–3)
- Private alpha with 10 design partners
- Weekly feedback sessions
- Iterate on onboarding and core workflow

### Beta (Month 4–5)
- Open beta with free trial
- Product Hunt launch
- Hacker News Show HN
- Blog post: "How we built CloudBuilder"

### Public Launch (Month 6)
- Full public launch with free trial
- Conference talks
- Partnership announcements
- Case studies from alpha users
