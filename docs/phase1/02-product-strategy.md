# CloudBuilder — Product Strategy

## Strategic Pillars

### 1. Visual-First Infrastructure Design
- Differentiate from code-only tools (Terraform, Pulumi, CDK)
- Compete with diagram tools (LucidChart, Draw.io) + Brainboard
- Position as "GitHub for Infrastructure Design"

### 2. End-to-End Lifecycle Coverage
- Single platform covering design → provision → observe → optimize
- Eliminate toolchain fragmentation
- Reduce cognitive load on platform teams

### 3. AI-Augmented Operations
- Predictive cost analysis
- Automated root cause identification
- Intelligent incident response
- Natural language infrastructure queries

### 4. Community-Driven Open Source
- Open core model (OSS core + enterprise features)
- Plugin ecosystem for extensibility
- Provider-agnostic with Terraform/OpenTofu as output

## Go-to-Market Strategy

### Phase 1 — Foundation (Months 1-6)
- Open source release on GitHub
- Focus on CloudBuilder Design + Provision modules
- Target early adopter platform engineering teams
- Content marketing: blog posts, architecture guides

### Phase 2 — Growth (Months 6-12)
- CloudBuilder Observe + Cost modules
- Enterprise features (RBAC, audit, SSO)
- Partnerships with cloud providers
- Community program with contributors

### Phase 3 — Scale (Months 12+)
- CloudBuilder AI module
- CloudBuilder Platform (Service Catalog, Golden Paths)
- Enterprise sales team
- Managed Cloud offering

## Pricing Strategy (Enterprise)

- **Open Source**: Free, all core features
- **CloudBuilder Enterprise**: SSO, RBAC, Audit, Support — $/seat/month
- **CloudBuilder Cloud**: Hosted version — $/resource/month
- **CloudBuilder AI**: Premium AI features — $/analysis/month

| Against | Our Advantage |

| Datadog | Open source, integrated design |
